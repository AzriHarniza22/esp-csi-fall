## Urutan eksekusi & graf dependensi (DAG — putaran-4/5/6/8 review)

Bukan rantai linear yang dipaksakan — ini **DAG**. Panah = dependensi teknis; pekerjaan tanpa dependensi silang boleh jalan paralel (putaran-5 review #4). **Semua node host-side sampai Fase 5; hanya Fase V yang menyentuh perangkat (satu flash).**

```
Fase 0 (kontrak data)
  ├─→ Fase 1A (jalur CSI/adapter — host build+fixture, TANPA flash)   [level #1: run device di Fase V]
  ├─→ Fase 2 (recorder, timeline, anotasi kandidat host-side)
  └─→ Fase 3 (phase-aware training → model 5-kelas)  ← butuh output Fase 2

Fase 1B (prototype header + assert build-time, TANPA flash)               ← butuh 1A DAN Fase 3   [level #2: run device di Fase V]
Fase 4  (rekaman baru / E6 / karantina — firmware berjalan)               ← butuh 1A(host) + Fase 2 + spec 4.2a  (recorder ⊥ classifier; ⟂ 1B)
Fase 4B (final retraining — host build + replay)                          ← butuh Fase 4 + metode Fase 3   [level #3 host/replay]
Fase 5  (runtime state machine — implementasi + validasi replay host)     ← butuh 4B (model final) + replay Fase 3
Fase V  (SATU sesi flash: decoder + inference + state machine + validasi) ← butuh semua build (1A/1B/4B/5) siap   [run device #1+#2+#3]
```

- **Linearisasi aman (salah satu topological order)**: `0 → 1A → 2 → 3 → 1B → 4 → 4B → 5 → V` — **SATU sesi flash di Fase V paling akhir; tidak ada flash di tengah**. Lane paralel host-side: **`Fase 1B ⟂ Fase 4`** (rekam data mentah tak butuh classifier; recorder ⊥ gerbang classifier); `1A ⟂ Fase 2 ⟂ sebagian Fase 3` (butuh Fase 0/1A saja).
- **Tidak ada lingkaran**: 1A (host) tidak butuh model final; 1B butuh keluaran Fase 3; Fase 2 anotasi = input Fase 3; **Fase 4 butuh build 1A(host) + recorder/timeline Fase 2 + spec label 4.2a — BUKAN 1B, dan cukup firmware berjalan (recorder ⊥ gate classifier)**; **Fase 4B = training ulang final pasca-ekspansi dataset** (host/replay; bergantung Fase 3 + Fase 4); Fase 5 butuh model final 4B + replay Fase 3 sah (host). **Fase V = satu-satunya titik flash**, butuh SEMUA build (1A/1B/4B/5) siap.
- **Tiga level validasi berbeda — JANGAN dicampur** (prinsip putaran-5/6 review): **#1** decoder menerima frame + decoding benar (1A.5) · **#2** classifier 5-kelas berjalan & berprediksi (1B.5) · **#3** **final end-to-end validation under controlled experimental conditions** (4B.3, replay + host) — **BUKAN otomatis bukti siap deployment produksi**. Ketiganya tetap **pengecekan TERPISAH**, hanya **run device-nya digabung ke satu sesi Fase V** (#2 & #3 memakai build final). Lulus #1≠#2; lulus #2≠#3; #3 tetap dibatasi cakupan dataset (lihat batas klaim Fase 4B).
- **Snapshot dataset untuk training paralel** (putaran-6 review #3): bila Fase 3 dan Fase 4 berjalan paralel, SETIAP training run memakai **snapshot/version dataset tetap**; recording baru DILARANG masuk diam-diam ke dataset yang sedang dipakai training (tiap hasil training harus reproducible terhadap versi dataset yang dinyatakan).
- **Fase 1A belum otomatis terizinkan** hanya karena urutan direvisi — tetap butuh mandat implementasi terpisah dari user.
